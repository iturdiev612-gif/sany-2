# SANY — техника и бронирование

React-каталог автосалона: русский, кыргызский и английский языки, адаптация для телефона, поиск, фильтры, избранное, сравнение и отдельная страница бронирования. Контакт: **+996 707 108 410**.

## Бронирование

Клиент выбирает технику и заполняет короткую форму. Для телефона доступны Кыргызстан (+996, 9 цифр), Россия (+7, 10 цифр) и Казахстан (+7, 10 цифр). По умолчанию выбран Кыргызстан; код страны указан отдельно, поле принимает только цифры. Сайт открывает WhatsApp с готовым сообщением на **996707108410**. Клиент нажимает «Отправить» в WhatsApp. Сам переход в WhatsApp ещё не подтверждает отправку или бронь: наличие и время подтверждает менеджер. Оплата через сайт не требуется.

Каталог и эта форма работают на Vercel без базы данных, паролей и платных API. Для автоматической отправки без участия клиента потребовалась бы отдельная интеграция WhatsApp Business; здесь используется обычная ссылка WhatsApp.

## Локальный запуск

Используйте **Node.js 22 и npm 10.9.9**, как при проверке Vercel. Версия Node.js закреплена в `package.json` и `.nvmrc`; GitHub Actions устанавливает npm 10.9.9 перед чистой установкой.

```powershell
npm ci
npm test
npm run test:ui
npm run build
npm start
```

Откройте адрес, который напечатает сервер, обычно `http://127.0.0.1:4173`. `npm run dev` запускает React для разработки. Форма WhatsApp работает и в этом режиме; для серверной админки используйте `npm start` после сборки.

## Загрузка в GitHub

Загружайте исходники проекта: `src`, `public`, `api`, `server`, `scripts`, `tests`, `.github`, `package.json`, **`package-lock.json`**, `vercel.json` и остальные файлы настроек.

Не загружайте `node_modules`, `.env.local`, `.data`, файлы паролей, `build`, `dist` и `outputs`. Они исключены через `.gitignore`. `package-lock.json` нужно сохранить: Vercel и GitHub Actions используют `npm ci` для воспроизводимой установки.

Если используете GitHub Desktop, добавьте эту папку как существующий репозиторий и нажмите Publish repository. Если используете терминал, проверьте `git status`, добавьте нужные изменения, создайте коммит и отправьте его в свой репозиторий GitHub. GitHub Actions автоматически запустит тесты и сборку при push и pull request.

## Публикация в Vercel

1. В Vercel выберите **Add New → Project** и импортируйте репозиторий GitHub.
2. Root Directory — папка с `package.json`. Если репозиторий содержит только этот проект, оставьте `./`.
3. Настройки уже заданы в `vercel.json`: Framework — **Create React App**, Install — **`npm ci`**, Build — **`npm run build`**, Output — **`build`**, Node.js — **22.x**.
4. Для обычного каталога и WhatsApp-бронирования переменные окружения не нужны. Нажмите **Deploy**.
5. Проверьте каталог, переход к бронированию и открытие формы по прямой ссылке после обновления страницы. `vercel.json` сохраняет маршруты React и не перенаправляет API или изображения на HTML.

Каждый следующий push в production-ветку запускает новое развёртывание. GitHub и Vercel не подключаются автоматически из этой папки: репозиторий и проект нужно выбрать в ваших аккаунтах.

## Необязательная админка на Vercel

Админка и старый серверный API сохранены. Они нужны, если вы хотите менять каталог без коммитов, вести серверный список заявок и статистику. Для WhatsApp-бронирования это не требуется.

Vercel Functions не используют локальную `.data`: данные должны храниться постоянно во внешней базе. Создайте Upstash Redis через Vercel Marketplace либо Upstash и добавьте **только на сервере** следующие Environment Variables:

| Переменная | Значение |
| --- | --- |
| `UPSTASH_REDIS_REST_URL` | REST URL базы Redis |
| `UPSTASH_REDIS_REST_TOKEN` | REST token с правом чтения и записи |
| `ADMIN_PASSWORD_SHA256` | SHA-256 надёжного пароля админки, 64 символа hex |
| `SANY_STORAGE_PREFIX` | Необязательно, например `sany:production:` |

Также поддерживаются имена `KV_REST_API_URL` и `KV_REST_API_TOKEN`, если интеграция выдала их. Не добавляйте к секретам префикс `REACT_APP_`: он помещает значения в клиентский JavaScript. Используйте отдельную базу или namespace для Preview, чтобы тестовые изменения не затрагивали Production. После изменения переменных сделайте Redeploy.

При настроенном хранилище и пароле админка доступна по `/#admin`. Сессии, изменения каталога и серверные заявки хранятся в Redis. Условные записи выполняются атомарно, чтобы ограничения попыток входа работали и между разными функциями. При отсутствии базы публичный каталог продолжает работать, а серверный API не сообщает об успешном сохранении заявок.

**Заявки из новой WhatsApp-формы не копируются в админку:** клиент отправляет их непосредственно в WhatsApp. Заявки старого `/api/leads` появляются в админке только при использовании этого API.

## Локальное управление и другие хостинги

Локальный сервер сохраняет данные в `.data/`. Пароль существующей локальной копии хранится отдельно от исходников. Для новой установки `node scripts/setup-admin.cjs` создаёт пароль и его SHA-256; существующие файлы не перезаписываются. `.env.local` и файл доступа нельзя публиковать. Для изолированных проверок можно указать другой каталог переменной `SANY_DATA_DIR`.

Для прежнего хостинга Sites/Cloudflare оставлена отдельная команда **`npm run build:sites`**. Она собирает Worker в `dist/server/index.js`; `.openai/hosting.json` содержит существующий ID проекта и binding R2 `BUCKET`. Обычная команда `npm run build` собирает только клиент для Vercel и локального сервера.

Настройки и данные разных хостингов не переносятся автоматически. Для другого Node-хостинга нужен постоянный диск для `.data`, HTTPS и резервные копии.

## Данные каталога

Цены, мощность, грузоподъёмность, годы выпуска и наличие не выдуманы. Пока продавец не подтвердит данные, сайт показывает «Уточняется» или «Цена по запросу». Внешнее описание и колёсные формулы требуют проверки продавцом. Фотографии обработаны AI для удаления окружения и служат иллюстрациями каталога.

`scripts/optimize-assets.cjs` нужен только для повторной обработки PNG; обычная сборка не требует Sharp.

Технические справки: [настройки Vercel](https://vercel.com/docs/project-configuration/vercel-json), [Node.js Functions](https://vercel.com/docs/functions/runtimes/node-js), [постоянное хранение вместо файлов Functions](https://vercel.com/kb/guide/how-can-i-use-files-in-serverless-functions), [Upstash REST API](https://upstash.com/docs/redis/features/restapi).

## Если Vercel пишет Missing: yaml from lock file

Исправленный `package-lock.json` включает нужную зависимость YAML 2 для Tailwind. Замените корневой `package-lock.json` в GitHub версией из актуального архива и создайте новый коммит. Vercel должен собирать этот новый коммит, а не повторять старый deployment с прежними исходниками. Install Command оставьте `npm ci`.

Изолированная чистая установка проверена на Node.js 22.23.4 / npm 10.9.9. Она не использовала заранее установленные пакеты из рабочей папки проекта. Для обновления зависимостей используйте npm 10.9.9 и сохраняйте lock-файл в GitHub вместе с `package.json`.
